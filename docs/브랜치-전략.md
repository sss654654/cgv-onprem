# 브랜치 전략

trunk 하나(`main`)와 짧게 사는 작업 브랜치를 쓴다. **환경 브랜치를 두지 않는다.**

---

## 브랜치

| | |
|---|---|
| `main` | trunk. 직접 push 하지 않고 MR 로만 들어간다 |
| `<종류>/<무엇>` | 작업 브랜치. 머지하면 삭제된다 |

종류는 실제로 쓰는 것이 이렇다 — `feat` · `fix` · `perf` · `refactor` · `ci` · `docs` · `chore`.

```
feat/seat-inventory-gauge
fix/board-single-flight
ci/trunk-to-main
```

## 머지

```
MR 을 연다 → CI 게이트를 통과한다 → 스쿼시 머지 → 소스 브랜치 삭제
```

스쿼시라 `main` 의 커밋 하나가 MR 하나다. 커밋 메시지에는 **무엇을 왜 바꿨는지**를 적는다.

---

## 브랜치는 환경이 아니다

어느 환경이 무엇을 도는지는 배포 저장소([cgv-infra](https://github.com/sss654654/cgv-infra))의 `envs/<환경>/` 폴더가 갖는다. 이 저장소의 브랜치는 그것과 무관하다.

**환경 브랜치를 안 쓰는 이유는 이미지 때문이다.**

```
브랜치가 환경이면 브랜치마다 CI 가 돌아 이미지를 다시 만든다
→ 검증한 이미지와 배포된 이미지가 다른 결과물이 된다
```

이 서비스는 온프레미스와 클라우드에서 같은 부하를 재서 비교하는 것이 목적이라, 두 환경의 이미지가 바이트까지 같아야 한다. 그래서 이미지를 한 번만 만들고 이름을 더 달아 옮긴다.

---

## 이미지 태그

| 레지스트리 | 태그 | 쓰는 곳 |
|---|---|---|
| GitLab 레지스트리 | `main-<파이프라인번호>-<커밋해시>` | 온프레미스 클러스터 |
| ECR | `<커밋해시>` | 클라우드 환경 |

**ECR 쪽 이름에는 브랜치가 안 들어간다.** 같은 이미지를 여러 환경이 같은 이름으로 불러야 해서, 환경과 무관한 이름이어야 한다. 커밋 해시는 GitLab 쪽 태그의 마지막 조각과 같아서 둘이 짝이라는 것이 눈으로 찾힌다.

**같은 이름을 다시 쓰지 않는다.** 그래서 어느 태그가 어느 빌드인지가 항상 정해지고, 되돌릴 대상을 이름으로 지목할 수 있다.

---

## 승격

```
main 에 머지
  → CI 가 이미지를 만들어 GitLab 레지스트리에 올린다        항상
  → 온프레미스 클러스터가 자동으로 받는다                    봇이 배포 저장소의 태그를 갱신한다

publish-ecr 버튼을 누른다
  → 같은 이미지에 이름을 하나 더 달아 ECR 로 민다            ★ 다시 빌드하지 않는다
  → 클라우드 환경이 받는다
```

**버튼을 누르는 것이 승격 결정이다.** 누른 기록이 파이프라인에 남는다.

---

## 파이프라인이 도는 때

```
MR 사건                   check · test · build · scan
main 브랜치 push          위 넷 ＋ publish · cleanup.  publish-ecr 은 버튼
그 밖의 브랜치 push        안 돈다
```

일반 브랜치를 넣지 않는 이유는 같은 커밋이 두 번 도는 것을 막기 위해서다. push 한 뒤 MR 을 만들면 push 사건과 MR 생성 사건이 각각 파이프라인을 만든다. 브랜치 쪽을 trunk 하나로 좁히면 순서와 무관하게 하나가 된다. 대가는 일반 브랜치가 MR 을 열어야 CI 가 도는 것이다.

## 아직 없는 것

```
릴리스 태그 (semver)    환경이 둘이고 늘 최신이 도는 동안은 버전을 고정할 대상이 없다
                       여러 버전을 동시에 유지해야 할 때 도입한다

핫픽스 경로             trunk 와 배포된 것이 벌어질 일이 아직 없다
                       벌어지면 그 시점의 태그에서 release 브랜치를 임시로 딴다

기능 플래그             미완성 기능을 아직 브랜치에 둔다
                       브랜치 수명을 하루로 줄이려면 런타임에 끄는 수단이 필요해진다
```

셋 다 지금 필요가 없어서 안 넣은 것이고, 필요해지는 조건을 위에 적어 뒀다.
