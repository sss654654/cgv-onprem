# frontend — 티케팅 대기열 시뮬레이터 SPA + nginx 게이트웨이

브라우저가 접근하는 진입점이다. 바닐라 JS 단일 페이지 앱(SPA)과, 정적 파일을 서빙하면서 API를 뒤 서비스로 넘기는 nginx 리버스 프록시로 구성된다. 빌드 도구·프레임워크가 없다(HTML·CSS·JS 3파일).

화면은 **시뮬레이터**다 — 첫 화면 왼쪽이 서비스(스토리·아키텍처·전체 현황·예매 카드), 오른쪽이 시뮬레이터 콘솔(관객 투입·오픈 예약·자동 예매·실황)이고, 방문자가 가상 관객으로 대기열을 굴려보다 직접 줄을 서서 예매까지 해본다.

- 화면: 영화목록(+콘솔) → 대기 → 회차선택 → 좌석 → 결제 → 완료
- 게이트웨이: `/api/admission/*` → queue / 나머지 `/api/*` → booking
- 상태 전달: 서버 push 없음 — 클라이언트가 `GET /position`을 폴링

---

## 현재 상태

k3s에서는 라우팅 역할을 Traefik Ingress가 대신하며, nginx는 정적 파일만 서빙하는 파드로 남는다(경로 규칙은 그대로 이관 — 로컬 compose에서는 이 nginx가 게이트웨이까지 겸한다). 폰트는 외부 CDN(jsDelivr의 Pretendard)을 비블로킹으로 참조한다 — CDN이 막힌 망에서도 첫 화면이 비지 않고 시스템 폰트로 대체된다. 아키텍처 다이어그램의 아이콘은 Simple Icons(CC0)를 인라인 SVG 스프라이트로 심어 외부 요청이 없다.

## 시스템에서의 위치

```
   브라우저  (http://localhost:8088)
     │
     ▼
 ┌──────────────────────────────┐
 │  frontend (nginx, 이 서비스) │   정적: index.html · app.js · style.css
 │  = 정적 서버 + 리버스 프록시  │
 └───────┬──────────────┬───────┘
         │ /api/admission/*     │ 나머지 /api/*
         ▼                      ▼
      queue (8090)          booking (8091)
```

브라우저는 이 한 주소만 본다. 경로 접두로 뒤 서비스가 갈리며, 더 구체적인 `/api/admission/`이 `/api/`보다 우선한다. k3s에서는 이 규칙이 Ingress 매니페스트로 옮겨간다.

## 화면 흐름 (상태 머신)

```
        [로그인]  requestId 발급(localStorage)
            │
            ▼
   ┌──── movies ────┐  영화 클릭 → enter
   │        │                       │
   │        │  202 WAITING          │ 200 ADMITTED
   │        ▼                       │
   │     waiting  ──ADMITTED발견──▶ entering ──▶ screenings ──▶ seats ──▶ pay ──▶ done
   │   (순번 폴링)      (전환 유예)   (회차 선택)   (좌석 선택)  (결제)   (완료)
   │        │                                        │
   │        └── EXPIRED(타임아웃·이탈) ──────────────┘
   │                                                 │
   └──────────────────── 홈/뒤로 ────────────────────┘
```

- **waiting → entering**: 폴링 응답이 `ADMITTED`로 바뀌면 곧장 좌석으로 가지 않고 "입장 중…" 화면을 잠깐 거친다. queue의 승격과 booking의 admitted 채움 사이 시간차 때문에 좌석 조회가 403이 날 수 있어서, 그 사이 회차 조회를 재시도(최대 12회·0.3초 간격)해 흡수한다.
- **입장 후에도 느린 폴링 유지**: active가 된 뒤에도 5초 간격으로 `/position`을 계속 조회한다. 서버가 세션 타임아웃으로 자리를 회수하면(`EXPIRED`) 그것을 감지해 홈으로 돌린다.

## 클라이언트가 담당하는 것

서버가 stateless·폴링이라, 다음은 전부 클라이언트 몫이다.

| 관심사 | 구현 |
|---|---|
| 신원 | `requestId` = 로그인 시 발급하는 UUID, localStorage 지속. 모든 요청에 실린다 |
| 순번 조회 | `GET /position` 폴링. 순번이 뒤일수록 주기를 늘리고(1/2/5초), jitter를 더해 동시 폴링 herd를 분산 |
| 403 경쟁 | 입장 직후 좌석/회차 403을 치명 오류로 안 보고 짧게 재시도(비동기 시간차 흡수) |
| 카운트다운 | active 1분 타이머는 표시용. 실제 기준은 서버 세션 타임아웃이라, 로컬 타이머는 서버 감지 지연보다 넉넉한 마진 뒤에만 퇴장시킨다 |
| 새로고침 복구 | 진행 상태를 `cgv_flow`에 저장 → F5 후 같은 requestId로 enter 재호출(서버: active=유지 / waiting=꼬리로 밀림) |
| 네비게이션 정합 | 뒤로가기·홈은 화면만 바꾸지 않고 서버 상태를 맞춘다 — 좌석락 해제(`/release`)와 자리 반납(`/leave`)을 짝으로 호출. 안 하면 TTL까지 점유가 남는다 |

응답 상태코드별 화면 처리: 202→대기, 200→입장, 409→그 좌석만 회색+알림(전체 새로고침 없음), 403→미승인(재시도 또는 퇴장), 503 `RETRY_LATER`→지연 안내(화면 유지).

## 코드 구조

```
frontend/
├── index.html      화면 7종의 마크업(section) + 시뮬레이터 콘솔
├── js/
│   ├── core.js     상태(S)·저장소 래퍼·DOM 유틸·API 래퍼·포맷·실황 출력·게이트 판정
│   ├── live.js     서버가 정본인 것 — 전체 현황(stats)·실황(events) 폴링
│   ├── booking.js  서비스 여정 — 신원·영화 목록·입장·대기 폴링·회차·좌석·결제·완료
│   ├── sim.js      시뮬레이터 — 가상 관객 엔진·오픈 게이트 렌더/발동·콘솔
│   └── main.js     부팅과 배선 — 이벤트 연결·시계·상태 복구
├── style.css       디자인 토큰(색·타입 스케일·간격) 기반 스타일
├── og.png          링크 공유 카드
├── nginx.conf      라우팅 3분기 + SPA fallback + no-cache
└── Dockerfile      nginx-unprivileged(비루트 uid 101, 8080)
```

번들러가 없다. 브라우저 표준 ES 모듈(`<script type="module">`)로 나누고, 의존은 한 방향으로만 흐른다 — `core → live → booking → sim → main`. 순환이 생기지 않도록 게이트 판정처럼 양쪽이 쓰는 순수 로직은 `core`에 둔다.

상태를 한 곳에 모은 것이 규칙이다: 화면 상태는 `core.js`의 `S`, 브라우저에 남기는 값은 같은 파일의 `K`(키 목록)와 `store` 래퍼를 거친다. 저장소 키 문자열을 여기저기 적으면 지우는 곳과 쓰는 곳이 어긋난다.

## 시뮬레이터 콘솔

첫 화면 오른쪽에 상시 표시되는 조작판이다. 가상 관객·오픈 게이트는 전부 이 브라우저(탭 메모리·localStorage)의 것이고, 백엔드(대기열·좌석)는 모든 방문자가 공유한다 — 화면에도 같은 고지가 있다.

- **관객 투입** — 가상 관객 = 가짜 `requestId`로 enter하는 클라이언트. 3초 틱마다 전원이 `/position`을 폴링한다(6명씩 병렬 — 동일 오리진 동시연결 한도 안에서 원거리 RTT에도 생존 창을 지키기 위해). 폴링이 곧 생존 신호라 틱이 멈추면 대기자는 30초 만에 서버가 회수한다. 투입은 프리셋(최대 200명) — 이 상한은 브라우저 생성기의 물리(연결 6개로 30초 안에 전원 폴링)지 백엔드 정원이 아니고, 그 이상의 부하 실측은 k6 몫이다.
- **자동 예매** — 켜면 입장한 관객이 좌석을 잡고 예매하고 나간다(자리 순환이 실황에 흐른다). 끄면 세션 60초를 다 쓰고 나가 정원이 막힌 상황이 된다.
- **예매 오픈 예약** — 오픈 시각을 걸면 예매 버튼이 잠기고 시계가 카운트다운한다. 오픈 전 투입한 관객은 서버에 줄을 세우지 않고 대기실에 모아 뒀다가 오픈 순간 러시 인원과 함께 한꺼번에 줄을 세운다. 게이트는 localStorage 연출이라 서버는 이 시각을 모른다. 오픈 창은 10분, 지나면 자동 소멸한다.

## 게이트웨이 규칙 (nginx.conf)

```
location /api/admission/   → proxy_pass  queue        (입장 통제)
location /api/movies       → proxy_pass  booking      + 캐시 10초 · 캐시 잠금
location /api/             → proxy_pass  booking      (예매)
location /                 → try_files → index.html   (SPA fallback)
                             + Cache-Control: no-cache
```

- **`/api/movies`만 nginx가 캐시한다.** 영화 목록은 대기열 게이트 **앞**에 있는 경로라 정원이 막아 주지 못하고, 대기 중인 전원이 주기적으로 부른다 — 부하 판에서 이 경로 때문에 booking의 readiness 프로브가 떨어졌다. 목록은 영화가 추가될 때만 바뀌므로 초 단위로 낡아도 화면이 틀리지 않는다.
  - `proxy_cache_lock on` — 캐시가 빈 순간 booking으로 나가는 요청은 하나뿐이고 나머지는 기다린다. 이게 없으면 만료 순간마다 같은 몰림이 그대로 재현된다.
  - `proxy_cache_use_stale` — booking이 죽어도 낡은 목록으로 화면이 뜬다. 대기열은 계속 돈다.
  - 캐시 경로는 이미 붙어 있는 쓰기 가능한 emptyDir 안이다(`readOnlyRootFilesystem=true`라 그 밖은 못 쓴다).
  - `X-Cache-Status` 헤더로 HIT/MISS를 확인한다.
- **업스트림 주소는 변수로 둔다.** `proxy_pass`에 변수가 있으면 nginx가 이름을 기동 시점이 아니라 요청 시점에 푼다 — 뒷단 파드가 먼저 뜨지 않아도 nginx가 기동에 실패하지 않는다.
- 폴링 전환 후 SSE 스트림용 설정(버퍼 off·긴 타임아웃)은 제거했다. 짧은 요청·응답이라 불필요하다.
- 파일명에 해시가 없어 캐시버스팅 수단이 없으므로 `no-cache`로 재배포 시 구버전 노출을 막는다(조건부 요청이라 304로 처리된다).
- k3s에서는 Ingress가 `/api`를 먼저 가로채므로 이 proxy 규칙은 타지 않는다(그대로 둬도 무해).

## 실행

전체 스택은 루트에서 `docker compose up --build -d`로 띄운다. 브라우저 진입점은 http://localhost:8088. 빌드 단계가 없어 파일을 이미지에 복사만 하면 된다.

## 알려진 한계 / 다음

- **API가 무인증**: 시뮬레이터 조작 계열(enter 대량 투입)을 프론트가 막을 방법이 없다 — 상한·게이트는 연출이지 방어가 아니다. 서비스는 이 상태로 인터넷에 공개돼 있다. rate limit은 넣지 않기로 했다: 막고 싶은 것은 "한 출처가 여러 몫을 가져가는 것"인데 세는 것은 "출발지당 요청 수"라 재는 축이 다르고, CDN 엣지 뒤에서는 출발지가 전부 엣지 주소로 뭉친다. 좌석 오염은 주기 초기화(클러스터 쪽 CronJob)가 받고 대량 트래픽은 엣지가 앞에서 받는다.
- **좌석 폴링**: 좌석도는 5초 간격 새로고침으로 갱신한다(정확성은 서버의 409가 보장하므로 지연은 무해).
- **로비의 좌석 현황판은 CDN이 캐시한다**: 회차별 잔여 좌석 조회(`/api/screenings/board`)도 게이트 앞 경로라 대기 중인 전원이 3초마다 부른다. booking 응답에 `Cache-Control: max-age=5, public`을 붙여 엣지가 받게 했다 — TTL이 폴링 주기보다 커야 만료 순간과 폴링이 겹치지 않는다. 응답에 사용자별 내용이 없어(`requestId`를 받지 않는다) `public`으로 둘 수 있다. 회차 목록에는 같은 조치를 못 한다 — URL에 `requestId`가 들어가 사람마다 응답이 다르고, 캐시하면 입장하지 않은 사람이 입장한 사람의 응답을 받아 게이트가 무력해진다.
- **og:image 경로**: `og:image`가 `/og.png` 상대 경로다. 링크 공유 카드는 절대 URL을 요구하는 곳이 있어, 도메인을 잡는 단계에서 절대 경로로 바꾼다.
